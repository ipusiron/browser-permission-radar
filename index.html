📚 座学：ブラウザーの権限の基礎知識

各セクションを押すと開きます

Permissions API は、Web ページがブラウザーの機能（位置情報・カメラ・通知など）を使ってよいかの状態を、共通の方法で問い合わせる仕組みです。

  • 照会の書き方：navigator.permissions.query({ name: 'camera' })。答えは granted（許可済み）・prompt（使う前に尋ねられる）・denied（拒否済み）の3つ
  • このツールの表示：照会できなかった権限は、機能の API があれば unknown（照会できない）、なければ unsupported（機能なし）と分けて出す。unknown はスコアの平均に入れない
  • ブラウザーごとに照会できる名前が違う：Chromium 系（Chrome・Edge）は多く、Firefox・Safari は少ない。知らない名前は TypeError で拒否される
  • 通知だけは古い Notification.permission でも読める。未決定は default と返り、Permissions API の prompt にあたる
  • 照会で見えるのは、照会したページのオリジン（このツールなら https://ipusiron.github.io）への決定だけ。ほかのサイトに与えた許可は、どのページからも見えない
  • ほかのサイトの許可を確かめるには、ブラウザーの設定を開く（Chrome は chrome://settings/content、Edge は edge://settings/content、Firefox は about:preferences#privacy の「許可設定」）
  • 照会には利用者の操作が要らない。どのサイトも、開いた瞬間に同じ照会ができる。尋ねずに読めるこの情報は、ブラウザーを見分ける材料（指紋）にもなる
  • iframe に埋め込まれたページは、埋め込み元の Permissions Policy に従う。許されていない機能は、尋ねられずに denied になる

🟢 デバイスアクセス系

  • camera / microphone：盗撮・盗聴。許可を与えたサイトは、ページを開いている間ずっと使える
  • geolocation：行動の追跡・居場所の特定
  • midi：接続している MIDI 機器の構成が、ブラウザーを見分ける材料になる

🔵 データアクセス系

  • clipboard-read：コピーしたパスワードや機密情報の読み取り
  • clipboard-write：ClickFix と呼ばれる手口で悪用される。偽の CAPTCHA のボタンを押させ、裏で navigator.clipboard.writeText() により悪性のコマンドをクリップボードに書き込み、 「Win+R（ファイル名を指定して実行）やターミナルに貼り付けて実行して」と指示する（Microsoft Security Blog、2025年8月）。 Chromium 系ではこの書き込みに許可を求められない
  • persistent-storage：消されにくい保存領域。長く残る識別子・容量の圧迫
  • background-sync：ページを閉じたあとも Service Worker が同期できる。Chromium 系では既定で許可されている

🟣 通信・通知系

  • notifications：偽の警告の通知で、フィッシングサイトへ誘導する
  • push：ページを閉じていても届く。通知の許可と組み合わせて使われる
  • payment-handler：Web の決済アプリ。偽の決済画面の土台になりうる
  • idle-detection：操作していない・画面がロックされた、を検知する。在席・離席の監視
  • 今回のみの許可：Chrome（116以降のデスクトップ版）は、位置情報・カメラ・マイクで「今回のみ許可」を選べる。ページを閉じる・別のページへ移る・5分以上裏に置く・16時間たつ、のいずれかで失効し、granted から prompt に戻る
  • Firefox は、カメラ・マイクの問い合わせで「この決定を記憶する」を付けなければ一時的な許可になり、1時間たつかタブを閉じると消える
  • Safari は、拒否していても、実際にカメラ・位置情報などを要求するまでは prompt と答えることがある。また change の通知が届かないので、このツールのライブ更新は効かない
  • 尋ねられない権限：Chromium 系では background-sync・センサー・clipboard-write が既定で許可されている（このツールでは開いた直後から granted と出る）。persistent-storage は Chromium 系と Safari が利用状況で自動で決め、Firefox は尋ねる
  • このツールは change の通知を受け取り、ブラウザーの設定やアドレスバーの鍵のアイコンから許可を変えると、その場でレーダーとログに反映する
  • 最小権限の原則：必要最低限の権限だけを許可する
  • 定期的な見直し：ブラウザーの設定（サイトの設定・許可設定）から、使わなくなったサイトの許可を取り消す
  • オリジンの確認：許可する前に、問い合わせに表示されたサイトの名前（オリジン）が意図したものかを確かめる
  • すぐに止める：カメラ・マイクは使い終わったら止める（このツールも取得してすぐ止める）
  • 貼り付けて実行しない：ページの指示でコマンドを「ファイル名を指定して実行」やターミナルに貼り付けない（ClickFix 対策）
  • プライベートウィンドウ：一時的に試したいときは、プライベートウィンドウを使う
  1. 現在の状態を確認：「レーダー」タブで、このサイトに対する状態を見る（開いた直後から granted の権限は、尋ねずに許可されているもの）
  2. 権限を体験：「クイックテスト」で要求を出し、ブラウザーの問い合わせを体験する（カメラ・マイクはすぐ止め、座標・クリップボードの内容は表示しない）
  3. 変化を観察：許可・拒否のあと、レーダーとログが自動で変わる。鍵のアイコンから許可を取り消しても変わる
  4. 詳細を理解：「詳細」タブで、状態の出所（Permissions API／Notification.permission／照会できない理由）を確かめる
  5. リセット：ブラウザーの設定でこのサイトの許可を取り消し、「Cleanup」で Service Worker の登録を解除する
