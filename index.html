📚 座学：ブラウザ権限の基礎知識

Permissions API は、Webアプリケーションがブラウザの機能（位置情報、カメラ、通知など）にアクセスする際の許可状態を統一的に管理するための仕様です。

  • 統一仕様：W3Cによって標準化されているが、ブラウザごとに対応状況が異なる
  • オリジン単位の管理：許可した権限は https://example.com のようなオリジン（プロトコル + ドメイン + ポート）ごとに記録される
  • 4つの状態：
    • granted - 許可済み（アクセス可能）
    • prompt - 未決定（次回アクセス時にプロンプト表示）
    • denied - 拒否済み（アクセス不可）
    • unsupported - ブラウザ未対応（このツール独自の表示）

🟢 デバイスアクセス系

  • camera / microphone：盗撮・盗聴リスク。悪意あるサイトが無断で録画・録音する可能性
  • geolocation：位置情報追跡リスク。行動パターンの分析やストーキングに悪用される可能性
  • midi：デバイス指紋生成リスク。接続されているMIDI機器情報からユーザーを識別する可能性

🔵 データアクセス系

  • clipboard-read：パスワード窃取リスク。コピーした機密情報を無断で読み取られる可能性
  • clipboard-write：悪意あるコード注入リスク。クリップボードを書き換えて別のコマンドを実行させる可能性
  • persistent-storage：長期的トラッキングリスク。削除されにくいデータでユーザーを追跡する可能性
  • background-sync：意図しない通信リスク。バックグラウンドでデータを送信し続ける可能性

🟣 通信・通知系

  • notifications：フィッシング誘導リスク。偽の警告通知で悪意あるサイトへ誘導する可能性
  • push：バックグラウンド通信リスク。サーバーからのプッシュメッセージで行動を監視される可能性
  • payment-handler：不正決済リスク。偽の決済画面で金銭的被害を受ける可能性
  • idle-detection：行動監視リスク。ユーザーの活動パターンを分析される可能性
  • 永続的な権限：通知・位置情報・クリップボード書き込み等は、一度許可するとgranted状態が保持される
    💡 レーダーチャートの変化を確認するには、通知権限のテストを推奨
  • 一時的な権限：カメラ・マイクはgetUserMedia()で許可されるが、ストリーム停止後はpromptに戻る
    💡 これはプライバシー保護のためのブラウザの仕様
  • 状態の確認：Quick Testsで権限を許可した後、Rescan Allボタンでレーダーチャートを更新し、状態変化を観察できる
  • 最小権限の原則：必要最低限の権限のみを許可する
  • 定期的な見直し：ブラウザ設定から不要な権限を定期的に削除する
  • オリジンの確認：権限を許可する前に、URLバーでオリジンが正しいか確認する（フィッシングサイト対策）
  • 即座に停止：カメラ・マイクなどのデバイスアクセスは、使用後すぐに停止する（このツールも実践）
  • プライベートブラウジング活用：一時的に権限が必要な場合は、プライベートウィンドウを使用する
  1. 現在の状態を確認：まず「レーダー」タブで自分のブラウザの権限状態を確認
  2. 権限を体験：「Quick Tests」で安全に権限リクエストを体験（カメラ・マイクは即停止、位置情報・クリップボードは非表示）
  3. 変化を観察：Rescan Allでレーダーチャートの変化を確認
  4. 詳細を理解：「詳細」タブで各権限の状態を確認し、「?」アイコンでリスクを学習
  5. リセット：ブラウザ設定から権限をリセットし、最小権限の状態に戻す
